# CoordX「agent 防火墙」拆解：agent 之间到底怎么交互，新在哪

> 2026-11-07 · 视频：[CoordX: Make your agents behave when they go to work](https://www.youtube.com/watch?v=fEPVNFYJorA)（Ethereum & AI Engineering Group，11/04，70 分钟）。这页根据完整音频转写、[官方幻灯片](https://drive.google.com/file/d/1KQlETqP07s9Kn7zBPTgFmI6ibtt-6IF5/view)、[官网](https://coordx.ai) 和同日上线的论文 [arXiv:2611.06034](https://arxiv.org/abs/2611.06034) 整理。观点部分单独标出，只是个人看法，欢迎指正。

**一句话：** CoordX 让互不信任的 agent 不直接对话、也不进对方系统，只往一本“双方各持一份、自带规则”的共享账本上写字。技术零件大多有先例，新意主要在“专门做成给 agent 用”的那一层。

## 1. 谁在讲

- 主讲 Rob Ewin，CoordX CEO 兼联创，之前是 Nous Group 首任 Head of AI。
- CTO David Hyland-Wood 也在场，他是论文第一作者。
- 主持人 Peter Robinson 开场就说自己是团队的研究负责人，所以这算“自家人办的会”。

## 2. 要解决的问题

核心观点是“你的 agent 为你干活，对方的 agent 为对方干活”。利益不一致是做生意的常态，原话是 *divergent interests aren't misalignment*。现有工具都默认大家站同一边：

- **A2A 和邮件**：两边各记一份，事后对不上账。
- **MCP 和 API**：要把自己的系统开放给外人，规则由接入方一方说了算。
- **SaaS 平台、deal room**：所有人都得入驻，平台随时能改条款。
- **公链**：内容公开、要手续费、有延迟，私下交易其实用不着全局排序。
- **身份和权限产品**（Okta、Entra、AgentCore）：只管“谁能进”，不管“谈成了什么”，而且只管到自家边界为止。

## 3. agent 之间怎么交互（用比喻讲）

可以把它想成一本**复写式合同本**：

- 本子两边各有一份，内容一模一样，谁都没法偷偷改自己那份。
- 第一页印着规则（Type），比如“订单价格必须等于最后一次报价”“发票金额等于数量乘单价”。
- 每写一笔都要签名，谁写的一清二楚。
- 写完由邮差（中继）把复写页送给对方。邮差只拿到密封信封，看不到内容。
- 对方收到后先按规则检查，合规的才贴进自己的本子，不合规的直接扔掉。

### 拿 demo 里买 500 个钢支架走一遍

1. **加好友。** 双方交换身份和信箱地址。这只代表能联系上，不给任何权限。
2. **开本子。** 买方新建一条记录，套用 `deal/1` 规则，然后邀请供应商。供应商先看规则，同意了才加入。
3. **供应商报价 $14.50。** 它执行一条 `coordx do … quote`。客户端先按规则自查，再签名、加密，投进买方的信箱。
4. **买方收信。** 买方客户端依次检查签名、写入权限和规则，全部通过才记进本子。
5. **轮到谁了。** 买方 agent 执行 `coordx pending`，会看到“你欠一个动作：回应报价”。`coordx show` 显示的当前状态是双方各自从历史推算出来的，所以两边看到的一定一样。
6. **来回砍价。** 买方还价 12.50，供应商降到 13.50，买方下单 13.50。每一笔都挂在上一笔下面，形成一棵树。
7. **底线保密。** “最多出 14 块”这类信息只写在各自 agent 的任务说明里，从来不进记录。
8. **作弊被拦。** 供应商开出金额对不上的发票，买方客户端一算不等于 500 × 13.50，直接拒收。这张假发票永远进不了诚实一方的本子。

### 三种做法的对比

- **API 或 MCP**：对方 agent 进到你的系统里办事，规则由你定，对方只能相信你的记录。
- **邮件或 A2A**：双方互相传话，各记各的版本，吵起来说不清当初谈成了什么。
- **CoordX**：在中立地带摆一块自带裁判的棋盘。agent 只能在上面落子，规则由棋盘自己执行，双方的棋盘永远一致。

## 4. 机制要点（出自论文）

- **因果树**：每个条目只有一个父节点，不合并。状态由条目推算出来，不直接存储。分叉时协议不选赢家，不排时间顺序，也不需要全局共识，所以离线也能用。
- **权限也是条目**：grant 挂在树上某个位置，向下继承。每个条目注明自己是凭哪个 grant 写的，任何一方都能独立验证。
- **身份自主**：AID 是根密钥的哈希，概念来自 KERI。可以预先准备恢复密钥组，下面分 controller 和 persona 两层，一个根能派生出多个 persona。
- **只认正面证据**：规则不能依赖“我没看到某条消息”。所以协议**没有撤销**，要排除某个参与方只能换新密钥。
- **中继是盲的**：中继看不到内容，但能看到时间、包大小和网络地址。
- **Type 是声明式 TOML 脚本**：由各方客户端里的解释器执行。cookbook 里的 Type 大多是 Claude 写的，简单的约 50 行，国际象棋约 500 行。

### 给 agent 用的那一层

- CLI 输出 JSON，并附上“下一步可以做什么”。`rehearsal` 可以先试跑一遍，看会写入什么再提交。agent 零说明书也能上手。
- `coordx-type new / build / try / publish`：agent 可以自己写规则，并在本地用多方剧本先跑通。
- 客服台 demo 里，每个 agent 只被允许执行 `coordx pending/show/do` 三个命令。这就是“agent 防火墙”的实际含义。

## 5. Demo 清单

- **井字棋**：对手是被要求作弊的 Claude agent。它试过覆盖已下的格子、下到第 9 格、抢先手，全部被拒绝。
- **买卖谈判**：见第 3 节。
- **三 agent 客服台**：客户、一线客服、主管三个角色，有的工单必须由主管审批。
- 只展示过、没演示的例子：国际象棋、只有一手牌的扑克、看板认领、一次性 AWS 密钥、餐厅订座（超过 8 人自动拒绝并转人工）、点对点 token 转账。

## 6. 现状（已核对）

- 论文第 17 节写明是 release candidate，**不能用于生产**。转为正式标准前设了 6 道门槛，其中一条是要有两个独立实现能够互通。
- 官网标着 Developer preview，托管方案还在 waitlist。演讲里说一两周内放出客户端和中继的二进制，加上托管中继；目前的 alpha 只有 Mac app。
- 截至 11/07，GitHub 上**还找不到他们的代码**。演讲里说会开源引擎。
- “代码量只要十分之一”是让 Claude 估算的，没有实测。

## 7. 新在哪？（个人观点）

**技术零件大多有先例：**

- 只有交易双方持有记录、按合约校验、不全网广播：R3 Corda（2016），以及 Canton/DAML。
- 每人一条签名追加日志，中继负责转发：Secure Scuttlebutt、Nostr。
- 每个应用自带校验规则，各节点自己检查，不要全局共识：Holochain。
- 权限是可以沿链验证的 capability：UCAN、Ink & Switch 的 Keyhive。
- AID 和预置恢复密钥：KERI。

（以上对比来自我对这些项目的了解，没有逐条重新核实。）

**值得看的取舍：**“只认正面证据”和“分叉不选赢家”很干净，比 CRDT 或 git 更贴合谈判这种你来我往、本来就不打算合并的场景。代价是没有撤销，同一个密钥环里也没有前向保密。

**真正的新意**在于把这套东西直接包装成 agent 能自学的工具，并且以“agent 只能碰共享记录、碰不到我的系统”作为隔离边界。现在 MCP 和 API 一开放就容易出事，银行也开始封 agent，这个说法踩在痛点上。

## 8. 疑点

1. **它只管记录里的东西。** 货有没有真的发、对方 agent 写的内容是真是假、里面有没有藏 prompt injection，都不在它的保证范围内。
2. **权力不对等。** 现场有人问：沃尔玛这样的强势方一句“走我的 API”就够了，凭什么用你的？Rob 也承认这个问题打不破，打算先从各方地位相近的物流网络切入。Corda 当年技术也不差，最后也没普及开。
3. **demo 说服力有限。** 拦截非法棋步和不符的发票，普通服务端加校验逻辑也能做到。真正的卖点是“没有中间方也能做到”，但 demo 没讲清楚这为什么值钱。

## 9. 不用 CoordX 也能马上用的两点

- **让 agent 互相对抗。** Rob 的经验是，让 reviewer 或 tester agent 默认开发 agent 的产出很烂，直到被证明不是，否则它们会互相夸完就收工。
- **最小命令面。** 每个 agent 只给几个命令，一切交互都落在一份可审计的记录上。
